# SuperRich 換匯地圖實作計畫：修訂摘要

本檔記錄 [SuperRich USD／TWD 換匯地圖實作計畫](superrich-exchange-map-plan.zh-TW.md) 的版本演進。計畫本文只保留現行決定，不保留被推翻的內容；要理解某項決定「為什麼變成現在這樣」時讀這裡。

## 版本一覽

- 第二版（2026-09-08）：依對現有程式碼與 Netlify 官方文件的複查，修正平台限制、快照資料契約、marker 著色範圍、輪詢節奏與停用開關；新增分店資料來源的方案比較與來源使用限制章節。
- 第三版（2026-09-08）：查證來源站台的 robots.txt 與公開政策後重新界定來源使用風險；抓取降頻、降併發、新增 circuit breaker，免責聲明列為卡片必要元素。
- 第四版（2026-09-08）：移除營業時段限制（改由使用者點 Google Maps 自行確認）；依 review 修正五處錯誤——公開分店必須有目的地、預設關閉開關降回提案、停用開關改為執行期可即時生效、數值比較案例更正並定義單一縮放精度、前端刷新改排在失效之前。
- 第五版（2026-09-08）：使用者核准「顯示換匯點」開關且預設關閉，§3.1 由提案升為已確認需求。
- 第六版（2026-09-09）：補記使用者已同意每 30 分鐘更新，取代最初的每 15 分鐘需求；全天排程與共用結果維持不變。
- 第七版（2026-09-09）：使用者確認主動停用匯率服務時保留分店與連結；統一需求、訪客開關、卡片、排序、API 停用與重新啟用行為及驗收規則。
- 第八版（2026-09-09）：依使用者要求採用本次 review 建議；換匯點略過踩點類別／主題，補齊每 60 秒本站確認、no-store、過期後恢復、來源逾時／重試、封鎖優先序及控制版本，並補正官方條款查證。

## 第二版

| 項目 | 第一版 | 第二版 |
| --- | --- | --- |
| Function 結構 | 單一檔案兼排程與 API | 拆為排程檔與 HTTP 檔；排程 function 無法以 URL 呼叫 |
| 儲存一致性 | 未指定 | 讀取指定強一致性；新增 `@netlify/blobs` 相依；用 `getDeployStore()` 隔離環境 |
| 快照欄位 | 含「原始顯示字串」 | 只含數值與列舉；顯示文字全部來自 i18n（現行渲染層無跳脫處理） |
| 綠色標記 | 一項需求 | 拆為 D1 單店著色（必做）與 D2 群聚著色（可延後），並列出四處需修改的位置 |
| 目的地 key | 新增 chonburi／si-racha | （第二版改為不新增——第四版已證實此決定錯誤，見下） |
| 前端輪詢 | 每分鐘 | 依快照時間對齊 + 隨機抖動 |
| 停用方式 | 無 | `EXCHANGE_RATES_ENABLED` 環境變數 |
| 分店資料來源 | 直接假設 Notion | 列出 A／B／C 方案比較後採用 A |
| 來源使用限制 | 未提 | 新增章節：User-Agent、免責文字、失效與停用處置 |

## 第四版

| # | 項目 | 第三版 | 第四版 |
| --- | --- | --- | --- |
| 0 | 營業時間 | 只在泰國時間 08:00–21:00 抓取，非營業時段沿用最後報價並加標示 | **移除整套營業時段邏輯**。全天每 30 分鐘抓取（48 輪／日、約 1,296 請求）；不解析、不儲存、不顯示營業文字；新增 `fx_hours_note` 請使用者點 Google Maps 自行確認 |
| 1 | 公開分店目的地 | 第一版不新增 key，Chonburi／Si Racha 留空 | **修正錯誤**。`validateDestinations` 對 `Published` 列強制要求 Country Code + Destination Key，現有 14 筆空值全為未公開資料。第一版必須新增 `chonburi`、`si-racha` 至 `DESTINATIONS` 與 Notion 選項 |
| 2 | 預設可見度開關 | 列為已確認需求（預設關閉） | **降回提案**。已確認需求是分店與踩點直接一起顯示；開關與其預設值均待確認，未確認前不實作（第五版已獲使用者核准，見下） |
| 3 | 停用開關 | 只有 `EXCHANGE_RATES_ENABLED` 環境變數 | **修正錯誤**。Netlify 環境變數需重新部署才生效，不是即時 kill switch。改為 Blobs 控制旗標（執行期數秒生效）+ 環境變數作為建置期回退預設，手冊寫明兩者差異 |
| 4 | 數值比較 | 以 `0.8912` vs `0.89120` 為浮點誤判例子、每筆各自 `scale` | **修正錯誤**。該例子實測相等；真正風險是各列倍率不一致。改為全域單一 `RATE_SCALE = 1e6`、`rateScaledE6` 整數比較、`displayDecimals` 另存 |
| 5 | 前端刷新時機 | 到 `expiresAt` 之後才加抖動刷新 | **修正錯誤**。該設計在服務正常時也會固定閃一次「暫無報價」。新增 `nextUpdateAt`，刷新排在 `nextUpdateAt + jitter(0–30s)`，完整落在 `expiresAt` 之前 |

## 第七版

| 項目 | 決定與修正 |
| --- | --- |
| 主動停用 | 使用者確認保留分店與連結；管理者停用及 breaker 自動停用均只停止抓取與供應匯率，三列顯示「暫無報價」 |

| 生效範圍 | 區分後端下一次讀取控制旗標與前端下一次成功 API 查詢，不再承諾所有頁面於數秒內同步 |
| 待完成的工程修正 | 本次未處理快取期限、前端同步時限、報價過期後的恢復查詢、來源請求速率與時間預算，以及前次 review 的條款查證補正；這些不需要再確認產品選擇 |

## 第八版（現行）

| 項目 | 現行規則 |
| --- | --- |
| 篩選交互作用 | 換匯點不受踩點類別／主題影響，仍套用目的地、搜尋及收藏；新增雙語提示，補上選換匯類別後關閉開關的回退行為 |
| 兩種更新頻率 | SuperRich 全天每 30 分鐘抓取；換匯點開啟且頁面可見時每 60 秒查本站，切回頁面或恢復連線立即確認，不增加來源抓取輪次 |
| 快取與恢復 | API／CDN／瀏覽器 no-store；首次失敗或資料未到依 10s／20s／40s 再轉每 60 秒重試，過期撤價但不停止恢復；合併計時器、取消晚到回應、不延長同批有效期 |
| 請求預算 | 單輪最多 2 個同時請求，全域啟動間隔 200ms，約每秒最多 5 次；單次 5 秒、整輪來源 25 秒；全輪最多一次額外來源重試，403／429 不重試 |
| 封鎖與成功定義 | 403／429 優先停止新派送，一輪只升級一次；遵守較晚的 Retry-After；完整成功才清除全部封鎖紀錄，部分成功與整輪失敗分開計數 |
| 控制版本 | 每次停用／重新啟用產生新 controlVersion，抓取、快照、breaker 與 API 一致驗證；來源抓取前取得 etag，條件寫入失敗不覆蓋，新啟用不復用舊工作或價格 |
| 查證補正 | 補入官網 Terms & Conditions，其對公開匯率介面的適用範圍尚未確認；撤回「沒有明文禁止」及平均流量足以保證不造成負擔的推論 |
| 驗收與界線 | 第七版所列待補工程規則已寫入本文與驗收案例；仍需在實作時驗證來源時區、分店位置與正式環境執行時間。本次僅修訂計畫，未實作或部署 |

## 第九版（現行）

開工前複查。三次唯讀查證修正兩處來源事實，並補上會擋住 Phase A／B 的待決項目。

| 項目 | 第八版 | 第九版 |
| --- | --- | --- |
| `branchCode` 來源 | 記為 `/branch-client/{id}` 回傳 | **修正**：實測分店 10、34 的 `/branch-client/{id}` 只有 `id`／`latitude`／`longitude`／`googleLink`／`address`，沒有 `branchCode`；它在匯率回應的每筆報價項目內（分店 28 為 `M17`） |
| 匯率回應結構 | 記為 `data.exchange` 與 `data.time` | **修正**：根層為 `{ statusCode, code, message, timestamp, data }`，報價在 `data.exchange.<幣別>[]`。`data.time` 未在抽驗中出現，列為 Phase A 第一件待確認事項；若只有根層 `timestamp`，不得標成「官網報價時間」 |
| 官網報價時間 | 卡片顯示「官網報價時間」與「本次查詢時間」兩列 | **移除該列**。已確認 `data` 只有 `exchange`、報價項目無時間欄位、根層 `timestamp` 兩次查詢間變動而數字未變（即 API 回應時間）。卡片只顯示 `completedAt` 的「本次查詢時間」 |
| 面額對照 | 只說以 `unit`／`denomRem` 辨識 | 新增 §2.2 實測值：USD 的 `denomRem` 全集為 `100`／`50`／`20 - 10`／`5`／`1`，TWD 為 `2000 - 100`；只取完全相符的字串，其餘忽略 |
| `googleLink` 白名單 | 「Google Maps 網域白名單」未列舉 | 實測有兩種型式（`www.google.com/maps?cid=`、`maps.app.goo.gl`），白名單明確列出五個 host |
| 分店識別與對照檔 | 只說「小型、經驗證的連接設定」 | 新增 §9.1：採 `data/superrich-branches.json`（含 schema 與 `scripts/validate-superrich-mapping.mjs`），`netlify.toml` 的 `included_files` 需加入 |
| Notion 欄位填法 | 未定義 | 新增 §9.2 範本：`Icon`、`Notes`、`Source URL`／`Source Tags`、`Verification Status` 先 Paused 的理由 |
| 26 店目的地歸屬 | 只有規則，沒有清單 | 新增 §10 附錄：官方 ID 10–35 全表與建議 destination key，四筆標註需人工確認 |
| `exchangeRates` state | 只說「獨立 state」 | 定義 typedef 與「key 一律用 Slug」的理由 |
| 開關開啟時的計數 | 只定義關閉時 | 補上：`result-info` 含換匯分店、類別選項計數只計踩點，差額由 `fx_filter_note` 說明 |
| 排序選項初始態 | 未定義 | 開關開啟後、首次 API 結果前一律 disabled 而非隱藏 |
| 前端排程可測性 | §7 有十餘條時序驗收但無測試策略 | 要求實作為純函式 `nextExchangeAction(now, state) => { action, delayMs }`，計時器只是薄殼 |
| 命名與位置 | 未定 | `src/data/exchange-rates.js`（`RATE_SCALE` 與型別）、`scripts/exchange-rates-control.mjs` + `npm run fx:control`；`getDeployStore()` 也須帶 `consistency: 'strong'` |
